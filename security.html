安全日志

安全，是仓库数据的底线

项目经过「黑盒实测 + 代码审查 + 依赖扫描」三重安全审计。截至 v1.2.0，已发现的高危问题全部修复并复测通过，并持续披露。

黑盒实测

以攻击者视角对登录、鉴权、上传等关键面实测验证。

代码审查

逐行审查中间件、路由与数据层，杜绝逻辑越权与注入。

依赖扫描

扫描第三方依赖已知漏洞，及时升级并移除高风险包。

安全机制

9 项核心安全机制

密码哈希

bcrypt(12) 强哈希存储，明文永不落库。

参数化查询

Prisma ORM 全程参数化，杜绝 SQL 注入。

CSRF 防护

Origin 校验 + 白名单，跨站请求被拦截。

接口限流

基于真实客户端 IP 限流，防爆破与滥用。

安全响应头

HTTPS / HSTS / CSP 全量启用。

库存乐观锁

并发出库防超卖，账实一致。

两步验证（TOTP）

自研 RFC6238 实现、无第三方依赖；开启后登录需额外 6 位动态码，密钥生成 / 启用 / 关闭走独立鉴权接口。

上传魔数校验

按文件头嗅探真实类型 + 扩展名白名单 + crypto 随机文件名，杜绝改后缀上传 HTML 造成存储型 XSS。

Webhook 签名

回调携带 x-yc-signature（HMAC-SHA256），3 秒超时、记录 last_status，可及时发现被伪造或丢投的回调。

漏洞披露

已修复漏洞清单 · v1.0.1 → v1.2.0

编号 级别 问题 修复方案
1001 P0 middleware 任意 token 头放行导致越权 移除放行逻辑，/api/v1/* 由路由内部真实校验
1002 P0 验证码答案随前端下发可被绕过 服务端 SVG 生成 + 一次性校验，答案不下发
1003 P1 login-check 可被用于用户枚举 降级空壳，统一登录 / 重置错误文案
1004 P2 限流 IP 可被伪造头绕过 IP 取 X-Real-IP / XFF 末段真实客户端
1005 INFO 关键依赖存在已知风险 next 14.2.35 / next-auth 4.24.11；移除 puppeteer-core；xlsx → exceljs
1006 INFO 冗余配置扩大攻击面 关闭未使用图片优化器；CSRF 白名单移除 http 来源
1012 P0 安全复检发现九项隐患（含验证码可绕过、CSRF 基准可伪造、上传后缀绕过、弱密钥、Token 时序侧信道） 验证码在 authorize() 内一次性消费；CSRF 改用真实 Host；上传按魔数嗅探；弱密钥全站 503（fail-closed）；Token 定长比较；登录 IP + 账号双维度限速并统一文案
1029 P1 验证码错误提示不精确，难以区分「验证码错误 / 已过期」 新增只校验不消费的校验接口（带 IP 限流），账号密码错误仍统一文案，不引入用户名枚举面

注：v1.1.1 另有两条 P0 属可用性缺陷（新建商品 500、操作日志未落库），一并修复但不计入安全漏洞； v1.2.0 新增的两步验证、上传魔数校验与 Webhook 签名属主动加固，见上方「核心安全机制」。
